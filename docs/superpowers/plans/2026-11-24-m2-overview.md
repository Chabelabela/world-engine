# M2 Physics and Ships — Overview Plan

**Milestone goal (ROADMAP §5):** any block structure can become a rigid body with correct mass properties and fly in the surface frame.

**Exit:** build a rocket in creative mode and fly it. An off-centre thruster makes it tumble. Two players walk around on a moving ship and see the same thing. Twenty idle ships cost under 2 ms per tick.

**Why there are several plans:** as in M1, M2 mixes work that can be verified here with work that needs Minecraft:
- the physics core is pure Rust and runs in any session;
- ships on the server are checked by GameTests in CI;
- drawing ships is checked by client GameTests and by hand;
- riding and multiplayer are checked by GameTests and by hand.

Each phase gets its own plan that ends in working, tested software. Each plan is written just before its phase, with its code built and tested first (in CI for the Minecraft side), as for M1d–M1f.

**The order** follows what each phase needs to be checked:
- the core first, because everything else drives it;
- ships on the server before drawing them, because the sync and the renderer need ships that exist;
- drawing before riding, because riding is checked by looking;
- flight parts last, because until then a ship can be moved by commands.

## Design decisions made by the M2a probe

A Rapier 0.36 prototype was measured in the planning session (release build, one core). Its numbers are the evidence for these decisions. The M2a plan's tests keep the decisions true.

1. **Rapier 0.36 (`rapier3d-f64`).**
   - It is the roadmap's choice, and its current version has a native voxel shape, `Voxels`, with voxel–voxel contacts.
   - Its math types are glam-based. `glamx` 0.3.1 brings glam 0.33, so the core will hold two glam versions: ours (0.34.3, pinned for terrain) and Rapier's. Values cross between the two as plain `f64` arrays.
2. **Terrain is one `Voxels` collider per physics world**, edited a 16³ section at a time.
   - Measured: a frictionless ship sliding at 5 m/s over a floor made of one collider per 16 × 16 section catches on the first section edge: a 2 m/s upward kick, 33° of tilt, and it bounces back.
   - Over one `Voxels` collider it slides 100 m with 0.1 mm of vertical motion. Cuboid sections trip the same way as voxel sections.
   - Blocks whose collision shape isn't a full cube (slabs, stairs, fences, snow layers) are boxes, gathered into one compound collider per section. A ship sliding over partial blocks can still catch where two sections meet (a known limit).
3. **A ship is one `Voxels` collider for its full blocks, plus one compound of boxes for its partial blocks.**
   - Its mass, centre of mass and inertia are summed from per-block masses (each block a uniform box) and set on the body. The colliders themselves carry no mass.
   - Measured: a 4 × 4 × 4 ship rests within 0.07 mm of the floor and sleeps after 84 steps. A block resting on a slab rests at exactly y = 0. A 5³ ship rests stably on an 8 × 2 × 8 ship.
4. **Off-centre forces act as they should.** A 1,000 N force 1.5 m from the centre of mass of a 3,000 kg, 3 × 1 × 1 ship gives exactly the predicted angular velocity after one step (0.010000 rad/s).
5. **Fixed 60 Hz, three steps per server tick, on a dedicated physics thread.**
   - The thread owns the native world. The server thread queues commands and reads the snapshot published after the last batch of steps, one tick behind, and never waits.
   - GameTests run the same queue inline, so they are deterministic.
   - Results are reproducible on one platform but not bit-identical across platforms, which the server-authoritative design doesn't need. So the `enhanced-determinism` feature stays off.
6. **Gravity per ship.** World gravity is (0, −1, 0), and each ship's gravity scale is its local g. The host sets it every tick from the planet under the ship and its altitude: g·(R/(R+h))².
7. **No tunnelling at flight speeds.** A 2 × 2 × 2 ship falling at 150 or 300 m/s stops on a 1-block floor, with no CCD switched on for it: Rapier's speculative contacts, and its automatic CCD for fast bodies against fixed colliders, catch it.
   - Rapier caps speed at 400 m/s by default, so the probe's 1,000 m/s drop really hit at 400 m/s, and held too.
   - Surface-frame flight stops at about 150 m/s. M3 decides what orbital speeds need.
8. **Cost.**

   | Case | Measured |
   |---|---|
   | 20 ships of 1,000 blocks, at rest and asleep | 0.001 ms per step |
   | The same 20 ships, awake and sliding | 0.1–0.3 ms per step |
   | A 32,000-block ship: building its collider | 8 ms |
   | A 32,000-block ship asleep | 0.002 ms per step |

   The exit budget for idle ships (2 ms per tick) is about 600 times the measured cost. The real cost of idle ships will be in the Java host (terrain feeding and sync), which M2b and M2c measure.
9. **Waking.** Replacing the terrain collider's shape woke a resting ship, which then fell when the blocks under it were removed. The host also wakes ships near any terrain edit explicitly, so this doesn't depend on Rapier's internals.

## Verification environment

- **Rust:** `cargo test`, `clippy` and `fmt` in any session, including cloud sessions.
- **Java and Minecraft:** need JDK 25. Cloud sessions have JDK 21, so Java and Minecraft code is built and tested in CI first:
  - a temporary probe workflow applies the draft over the checkout;
  - the plan is written from what passed, and replays it byte for byte.
- **In-game:** GameTests on the server from M2b; client GameTests with screenshots from M2c; manual playtests at the end of each phase.

## Risks specific to M2

| Risk | Mitigation |
|---|---|
| **Rapier's voxel shape is new** (2025) and may have bugs or change between versions | Pin Rapier exactly. M2a's tests cover resting, sliding across section edges, stacking, partial blocks, edits and fast impacts, so a version bump that breaks them is caught. Fallback: greedy-merged boxes, which rest as well but catch on internal edges. |
| **Two glam versions** (ours for terrain, Rapier's) | Values cross as `f64` arrays inside `we-physics`. Terrain keeps its own pinned glam, so a Rapier bump can't change generated worlds. |
| **Feeding terrain to the core costs more than stepping it** | M2b sends only sections near ships, as 4,096-bit masks plus box lists, and only when they change. It measures the cost against the 2 ms budget. |
| **Partial blocks catch at section edges** | Known limit. If it shows in play, merge a section's partial boxes with its neighbours'. |
| **Vanilla movement checks fight players aboard a moving ship** | M2d's first task evaluates riding a ship entity on the server, which vanilla exempts from movement checks. |
| **Sodium and Iris** | M2c builds the Sodium mesher hook. M2e runs the ADR's E5 check again with Sodium. Iris shaderpacks are best effort (ROADMAP §6). |
| **Native crashes from a physics bug** | Every FFI entry point catches panics, as today. The physics thread turns a failed step into an exception, and the host marks the world broken and stops stepping instead of crashing the server. |
